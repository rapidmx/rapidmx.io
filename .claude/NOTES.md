decisions or re-discover the same issues from scratch. It is local to this repo (not tied to

## Standing decisions

- **What this repo is.** The marketing + documentation site for RapidMX, served from GitHub Pages
  at `https://rapidmx.io` (`static/CNAME`, `.github/workflows/deploy.yml`). Docusaurus 3, set up
  the same way as the sibling `d:\github\rapidrest\rapidrest.dev` site (same `future`/`faster`
  flags and the same rspack workaround). Three parts:
  - `src/pages/index.tsx` — the one-page landing page that sells RapidMX as a private,
    self-hosted replacement for Google Workspace and Microsoft 365.
  - `docs/` → `/docs` — for people who **run and use** a server: install, connect clients, use
    the features, administer and maintain it.
  - `developers/` → `/developers` — a second docs-plugin instance (`id: 'developers'`) for people
    who want to **contribute** to RapidMX or write plugins.
- **Sidebars are autogenerated** from folders. Order and labels come from `_category_.json` and
  `sidebar_position` front matter; adding a page never needs a `sidebars*.ts` edit.
- **`.md` is CommonMark, `.mdx` is MDX** (`markdown.format: 'detect'`). Write `.md` by default, so
  `<placeholder>` text and `{braces}` in prose and commands are safe. Use `.mdx` only for pages that
  need components (`<Tabs>`), and then escape `<`/`{` in prose. Mermaid diagrams work in both
  (```` ```mermaid ```` fences). Admonitions (`:::tip`, `:::note`, `:::warning`, `:::danger`) work in both.
- **Links:** `onBrokenLinks` and `onBrokenMarkdownLinks` both throw, so `yarn build` is the
  link checker. Link between pages with relative file paths including the extension
  (`../administration/domains.md`), which Docusaurus resolves and checks.
- **Accuracy over completeness.** Every statement about RapidMX must be traceable to the sibling
  repos' source, READMEs or charts (`d:\github\rapidmx\*`, `d:\github\rapidrest\auth-server`). Do not
  invent features, settings, menu labels, ports or defaults. UI labels should match the
  `web-client` source exactly. Where something is unreleased or a preview (e.g. `tauri-client`,
  `chat-plugin`), say so plainly on the page.
- **Never claim the RapidMX ACME CA (`acme.rapidmx.io`) is publicly trusted.** Its root is in no OS,
  browser or mail-client trust store.
- **There is no IMAP or POP3.** Clients connect through the web app, Exchange ActiveSync, MAPI over
  HTTP (Outlook) or the native app.
- **Commit discipline.** Don't `git commit` unless explicitly asked for *that specific piece of
  work*. Default to leaving changes uncommitted and saying so.
- **Commit message style:** a flat list of one-line, verb-led items — no summary/title line, no
  `-`/`*` bullet markers (same rule as every rapidmx/rapidrest repo; see `server/.claude/NOTES.md`).

### Prose style (carried over from rapidrest.dev, where it was corrected repeatedly)

- **Every page's opening needs to explain, not just define.** Before dropping into steps, tables or
  syntax, ground the reader: what problem this solves, a concrete scenario where they'd need it,
  and how it relates to its neighbours.
- **Audience for `docs/`:** an IT generalist or a technically-comfortable small-business owner who
  has run a Linux server or a Kubernetes cluster before, plus (for the user guide) ordinary
  employees who just want to read their mail. Don't explain what DNS, a container or `kubectl`
  are; do explain what's specific to RapidMX. User-guide pages assume no technical knowledge.
- **Audience for `developers/`:** a TypeScript/Node developer who has built a backend before. Do
  explain what's specific to RapidMX/RapidREST (decorator-driven DI and routes, plugin model).
- Minimize em dashes (" — "); split into separate sentences instead.
- Don't over-describe: cut tangential detail and restated context already on a sibling page. Link
  to it instead. Reference tables (settings, parameters, env vars) are the exception and stay
  exhaustive.
- Prefer numbered steps for procedures. Use concrete example values (`example.com`,
  `203.0.113.10`) over `<placeholder>` where a real-looking one works.
- Document one primary path, not every alternative.
- **No running comparisons to Google Workspace / Microsoft 365 in `docs/`.** The landing page is
  the place for that. In docs, a brief brand-free nod is fine; "unlike Gmail..." on every page is not.
- Helm values reference follows the Bitnami convention: `## Architecture`, `## Prerequisites`,
  `## Configuration and installation details`, then `## Parameters` as a single
  `| Name | Description | Value |` table with literal defaults in backticks.

## Session Log

### 2026-10-12 — Site created

- Scaffolded from scratch (not `create-docusaurus`), mirroring rapidrest.dev's config. Local search
  via `@easyops-cn/docusaurus-search-local` over both docs instances; Mermaid enabled.
- Brand tokens taken from `server/public/styles/globals.css` (teal `#0d9488` primary, gold accent,
  Blender Pro display font, Inter body). No Google Fonts or other third-party requests: Inter falls
  back to the system stack on purpose (privacy-first product).
- Landing-page section ids (`#features`, `#compare`...) are registered with
  `useBrokenLinks().collectAnchor` in `index.tsx`, or the build warns on every navbar/footer link.
- `docs/intro.md` has `slug: /`, so link to it as `/docs/`, never `/docs/intro`. Links from
  `developers/` into `docs/` (and back) must be URL paths: file links don't cross plugin instances.
- Landing-page claims deliberately toned down to match the code (verify before strengthening):
  Outlook for Windows (MAPI) is "in progress", since the last recorded status is a Connect/Bind loop;
  chat is "Coming soon" (chat-plugin is an empty skeleton); the encryption policy defaults to
  `optional`, not automatic; vault unlock by passkey isn't wired into the UI; calendar share links
  have no UI; scanner outage = ClamAV quarantines, rspamd sends to Junk.
- Screenshots in `static/img/screenshots` are stale: the wizard ones show Branding before Mailboxes
  (web-client 0.35 moved Branding last), `sign-in.png` shows RapidREST branding, and the inbox is
  empty. Retake them, ideally with a populated inbox for the landing page hero.
- The section agents' full lists of source contradictions and unverified points (stale READMEs,
  Helm values that do nothing, possible unauthenticated `/api/metrics` on Helm, AWS `gp3`/
  `trustedAuthservId` gaps, untested backup commands, no SECURITY.md in any repo...) were reported
  to the maintainer in the session summary; the docs follow the code where they disagree.
